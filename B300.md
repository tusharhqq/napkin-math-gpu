# NVIDIA B300 napkin math

This is a vendor-ceiling planning profile for one B300 SXM GPU. It is not yet a
calibrated Modal profile; achieved application throughput will be lower and
shape-dependent.

[General equations](README.md) · [H100](H100.md) · [B200](B200.md)

## Memorize these

| B300 SXM metric | Planning number |
| --- | ---: |
| HBM capacity | **288 GB** |
| HBM bandwidth ceiling | **8 TB/s** |
| Dense BF16/FP16 ceiling | **2.25 PFLOP/s** |
| Dense BF16/FP16 ridge point | **280 FLOP/byte** |
| Dense FP4 ceiling | **13.5 PFLOP/s** |
| NVLink GPU-to-GPU ceiling | **1.8 TB/s** |

B300's clear advantages over B200 are capacity and low-precision/attention
performance. NVIDIA's current HGX tables give B200 and B300 the same HBM
bandwidth and BF16/FP16 peak; do not assume every workload becomes faster just
because the model number is newer.

## Dense roofline ceilings

| Precision | Per-GPU compute | Ridge at 8 TB/s |
| --- | ---: | ---: |
| FP4 | 13.5 PFLOP/s | 1,688 FLOP/byte |
| FP8/FP6 | 4.5 PFLOP/s | 563 FLOP/byte |
| BF16/FP16 | 2.25 PFLOP/s | 281 FLOP/byte |
| TF32 | 1.125 PFLOP/s | 141 FLOP/byte |
| FP32 | 75 TFLOP/s | 9 FLOP/byte |

The FP4 value is NVIDIA's 108 PFLOP/s dense HGX B300 figure divided across
eight GPUs. For the FP8/FP6, BF16/FP16, and TF32 rows, NVIDIA publishes sparse
figures and states that dense throughput is half. These ceilings assume Tensor
Core-compatible operations where applicable.

## Quick capacity comparison

At the bare weight-only lower bound:

```text
maximum parameters = memory bytes × 8 / bits per parameter
```

| Weight format | 288 GB weight-only limit |
| --- | ---: |
| BF16/FP16 (16-bit) | 144B parameters |
| FP8 (8-bit) | 288B parameters |
| FP4 (4-bit) | 576B parameters |

Those are not deployable model-size promises. KV cache, activations, runtime
state, communication buffers, workspaces, and fragmentation all consume part
of the 288 GB.

## Modal request and live identity

Use `gpu="B300"`. Modal requires a CUDA 13.1-or-newer software stack for B300;
that compatibility constraint matters even when code already runs on B200. A
live Modal allocation on 2026-08-09 reported:

```text
NVIDIA B300 SXM6 AC, 275040 MiB, compute capability 10.3
```

Host-transfer speed, launch latency, achieved HBM bandwidth, and achieved GEMM
throughput are intentionally absent until a pinned full calibration exists.
